WD ProxKey / Watchdata DSC token not working on macOS? Here's the actual fix.

If a Watchdata ProxKey (or any Watchdata TimeCos/PK-based DSC token, rebranded by CAs like eMudhra, Capricorn, Sify, or Pantasign) doesn't work on your Mac — driver installed, buttons greyed out, JSignPdf hangs — this page explains exactly why and how to fix it permanently.

Short answer: it's not your Mac, your token, or your certificate. Watchdata's own macOS driver has a locking bug (a background helper it installs, ProxkeyCertMND, holds an exclusive device lock forever), and JSignPdf 2.3.0 needs an older JDK than what ships by default. Both are fixable in a few minutes.

Symptoms this fixes

  • ProxKey Token Tool.app — every button (User Login, Change PIN, Import Cert…) stays permanently greyed out / disabled
  • pkcs11-tool --list-slots hangs forever and never returns
  • JSignPdf's "Load keys" button hangs indefinitely, PIN prompt never appears
  • Java: NoClassDefFoundError: sun/security/action/GetPropertyAction
  • Java: IllegalAccessException … module jdk.crypto.cryptoki does not export sun.security.pkcs11
  • Java: IllegalAccessError … cannot access class sun.security.util.Debug
  • WD ProxKey / Watchdata token not detected on macOS Sonoma / Sequoia / Tahoe, Apple Silicon or Intel
  • DSC token works fine on Windows but does nothing when plugged into a Mac

Root cause

Watchdata's libwdpkcs_Proxkey.dylib calls a function called StartMutexDevice before it will talk to the token, which acquires a Cocoa NSDistributedLock to serialize device access. A separate background helper Watchdata installs, ProxkeyCertMND, grabs that same lock on launch and never releases it — so every other PKCS#11 client, including Watchdata's own GUI, spins forever waiting for a lock that's never coming free. Diagnosed via an lldb backtrace on the hung process and disassembly of the locking function — full writeup in the repo's technical appendix.

Install (one line)

curl -fsSL https://raw.githubusercontent.com/suvrashaw/proxkey-jsignpdf-macos/main/install.sh | bash

Automates everything that's safe to automate — cloning, Java 11, and disabling the lock-holding daemon. It can't install Watchdata's driver package or run sudo unattended (different vendors, different URLs), so it prints exactly what's left. Details below, or in the repo's Setup section.

The fix, summarized

# 1. Install Watchdata's official macOS driver (proxkey_mac.pkg from your vendor)

# 2. Let Watchdata's CCID driver own the reader
sudo defaults write /Library/Preferences/com.apple.security.smartcard useIFDCCID -bool yes

# 3. Disable the buggy lock-holding helper — the actual fix
pkill -f ProxkeyCertMND
launchctl disable gui/$(id -u)/com.watchdata.proxkey.launchd.certmnd

# 4. Run JSignPdf on Java 11, not your system Java
brew install --cask temurin@11

FAQ

Does WD ProxKey / Watchdata work on macOS at all?
Yes, but only after fixing the two bugs above. There is no working configuration that skips both fixes.
Why are all the buttons in ProxKey Token Tool greyed out on Mac?
ProxkeyCertMND is holding the device lock. Disable it and the buttons work immediately.
Why does pkcs11-tool --list-slots / JSignPdf's "Load keys" hang forever?
Same cause — it will not time out on its own. Kill ProxkeyCertMND and retry.
What Java version does JSignPdf need?
Java 11 specifically — newer JDKs removed internal classes JSignPdf 2.3.0's PKCS#11 code depends on.
Does this work on Apple Silicon or only Intel Macs?
Both — Watchdata's driver ships as a universal binary and the bug reproduces on both architectures.
Is this specific to the ProxKey brand, or does it affect other DSC tokens too?
Any Watchdata TimeCos/PK-based token, regardless of which Certifying Authority issued it, is very likely affected.
Can I sign PDFs on Mac without a Windows license or a VM?
Yes — that's the entire point of this project. No VM, no Windows, no Wine.
